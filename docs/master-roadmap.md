# Master Roadmap: From Zero to AI Systems Builder

This document is the core learning map for this repository. It is designed for a learner who wants to move from zero technical foundation toward deep mastery in:

- computer science
- Python programming
- Linux and systems
- software engineering
- AI / ML / MLOps
- cybersecurity
- embedded systems and robotics
- project execution and portfolio building

The path is intentionally structured in a linear order, but each phase is still connected to the next one. This is not random topic collection; this is a deliberate system of learning.

## Learning principle

The correct sequence is:

1. Build solid thinking and learning habits.
2. Learn math and logic.
3. Learn programming with one language deeply.
4. Learn Linux, data structures, and systems.
5. Learn software engineering.
6. Learn AI and data foundations.
7. Expand into security and hardware.
8. Build projects and capstones.
9. Iterate, refine, and ship.

## Phase 0 — Foundations of learning and cognition

Goal: build the ability to learn efficiently and think scientifically.

Topics:
- meta-learning
- spaced repetition
- Feynman technique
- first-principles thinking
- systems thinking
- scientific method and epistemology
- logic and proof basics
- disciplined study workflow

Deliverables:
- study system that is repeatable
- clear note-taking system
- ability to explain concepts in simple language
- ability to identify what is known vs unknown

## Phase 1 — Mathematical foundation

Goal: build the analytical engine needed for CS, ML, AI, and technical reasoning.

Topics:
- set theory
- discrete math
- combinatorics
- number theory
- algebra basics
- linear algebra
- probability
- statistics
- calculus basics
- graph theory
- optimization basics

Deliverables:
- comfort with mathematical abstraction
- ability to read technical explanations without confusion
- understanding of probability and statistics for modeling

## Phase 2 — Programming foundation with Python

Goal: learn how to reason, construct programs, and solve problems.

Topics:
- Python basics
- variables, functions, loops, conditions
- data structures
- recursion and iteration
- objects and classes
- file I/O
- modules and packages
- testing and debugging
- algorithmic thinking
- command-line tools

Deliverables:
- readable Python code
- working CLI tools
- strong debugging habits
- ability to solve medium-level coding problems

## Phase 3 — CS core and systems thinking

Goal: understand how software and computers really work.

Topics:
- algorithm complexity
- sorting and searching
- trees, graphs, hash tables
- memory and CPU basics
- operating systems basics
- shell and Linux navigation
- process and threads
- networking fundamentals
- databases basics
- system design basics

Deliverables:
- deep understanding of data structures and algorithms
- comfort with Linux terminal
- ability to reason about program execution and system behavior

## Phase 4 — Software engineering and backend fundamentals

Goal: build real software, not just toy scripts.

Topics:
- clean code
- testing and debugging
- Git workflows
- REST APIs
- SQL and databases
- authentication and authorization
- networking and HTTP
- design patterns
- architectural thinking
- CI/CD basics
- observability basics

Deliverables:
- one or more working APIs/applications
- well-structured codebase
- project workflow habits
- ability to explain architecture decisions

## Phase 5 — AI foundations and data science

Goal: move from programming into intelligent systems.

Topics:
- Python for data work
- NumPy and Pandas
- visualization
- statistics and math for ML
- feature engineering
- classical ML
- model evaluation
- deep learning basics
- neural networks
- CV and NLP fundamentals
- transformers
- RAG and LLM applications

Deliverables:
- train and evaluate models
- build a realistic ML workflow
- understand bias, validation, and deployment trade-offs

## Phase 6 — AI systems and MLOps

Goal: build systems that deploy and operate AI in real environments.

Topics:
- model lifecycle
- experiment tracking
- pipelines
- model serving
- feature stores
- APIs for model access
- monitoring and drift
- inference optimization
- model security
- deployment patterns
- AI product thinking

Deliverables:
- production-like AI project
- end-to-end pipeline from data to model to app
- practical MLOps awareness

## Phase 7 — Cybersecurity foundations

Goal: learn how systems can fail, be attacked, and be protected.

Topics:
- Linux security
- networking security
- web security
- cryptography basics
- OWASP top 10
- secure coding
- threat modeling
- reverse engineering basics
- incident response
- defensive security fundamentals

Deliverables:
- secure-by-default mindset
- understanding of attack surfaces
- ability to reason about vulnerabilities
- practical security awareness for real systems

## Phase 8 — Embedded systems, hardware, and robotics

Goal: connect software with physical systems and real-world control.

Topics:
- electronics basics
- digital logic
- microcontrollers
- C/C++ embedded
- GPIO, UART, SPI, I2C
- sensors and actuators
- timers, interrupts, PWM
- embedded OS basics
- control theory basics
- robotics and kinematics
- ROS2 basics

Deliverables:
- working embedded prototype
- sensor-control project
- robotics or automation experiment
- understanding of cyber-physical systems

## Phase 9 — Portfolio, capstone, and public proof

Goal: turn learning into evidence.

Types of projects:
- AI product with deployment
- secure API and service
- embedded device or robotics project
- data pipeline + analytics dashboard
- full-stack application with backend and frontend

Requirements:
- project must solve a real problem
- project must be documented
- project must have clear architecture
- project must be validated with testing or evidence
- project must show iteration and learning

## Dependence map

The strongest dependency tree is:

- math -> programming -> CS -> software engineering -> AI
- Linux -> systems -> networking -> cybersecurity
- electronics -> digital logic -> embedded -> robotics
- data -> ML -> AI systems -> productization

This means you do not need to master every field equally. You need to master the prerequisites before each branch.

## Recommended study rhythm

A sustainable rhythm is:

- daily learning blocks
- weekly project work
- monthly review and reflection
- milestone-based progression
- active recall and summarization

## What success looks like

A successful learner following this roadmap should be able to:

- reason clearly about systems
- write clean technical code
- debug effectively
- understand how software, data, and hardware connect
- build AI-enabled products
- secure systems sensibly
- design small real-world projects
- communicate technical decisions well

This is the path from learning to capability.
