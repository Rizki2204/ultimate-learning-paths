# Domain Map and Learning Architecture

This document explains how the repository is structured as a connected learning system.

## Core principle

The repository is not built as isolated topics. It is built as an interconnected knowledge graph.

## Main learning domains

- Foundations
- Programming
- Computer Science
- Linux and Systems
- Software Engineering
- Data and AI
- Cybersecurity
- Embedded Systems and Robotics
- Product and Portfolio Development

## Dependency chain

### Foundation chain
- logic -> math -> probability -> statistics -> abstraction -> system reasoning

### Systems chain
- Python -> Linux -> networking -> OS -> software -> architecture

### AI chain
- data -> math -> ML -> deep learning -> LLMs -> deployment -> product integration

### Hardware chain
- electronics -> microcontrollers -> sensors -> control -> robotics -> autonomous systems

### Security chain
- Linux -> systems -> networking -> secure coding -> threat modeling -> defense

## How to move through the repo

1. Start with foundation documents.
2. Move to CS core and programming.
3. Use Linux and systems as the operating environment.
4. Build software engineering skills.
5. Learn AI and ML from data to deployment.
6. Add security and hardware as supporting domains.
7. Complete projects and portfolio artifacts.

## Practical guidance

- Do not chase every high-level topic at once.
- Maintain one main track: AI systems.
- Learn adjacent domains as supporting layers.
- Build proof through projects and demos.

## Long-term goal

The final system is: foundation + CS + Python + AI + system engineering + secure product thinking.
